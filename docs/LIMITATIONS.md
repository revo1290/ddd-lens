# 既知の限界

## 自動解析で確認できないこと

- 会話で本当にユビキタス言語が使われているか
- bounded contextが業務上の意味で切られているか
- 集約境界が実際の整合性要件に合うか
- チーム間の交渉、所有権、意思決定速度
- モデルが障害や変更コストを実際に減らしたか

## 誤検知しやすいこと

- `domain` や `model` というディレクトリ名
- `Entity`、`Aggregate`、`Repository` という型名
- ORM/DIアノテーションの存在
- `adapter`、`translator` という命名
- DDD用語を含むREADMEやサンプルコード

このため、自動検出は原則2/4を上限とし、人が強い根拠を追加しない限り高確信度にしません。

## セキュリティとプライバシー

CLIはローカルで動作し、ネットワーク送信を行いません。出力には一致行の最大180文字が含まれるため、機密語が出力され得ます。機密環境では `scan.exclude` で対象外にし、共有前にレポートを確認してください。

## 現在の技術的制約

- AST解析ではなく言語横断の保守的ヒューリスティック
- Git履歴の変更結合度分析は未実装
- モノレポ内の複数評価スコープの自動分割は未実装
- 日本語形態素解析は未実装
- SARIFは重大な指摘のみを出力し、未評価項目は出力しない
